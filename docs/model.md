# Модель данных OrderFlow

Система хранит покупателей, адреса, каталог, заказы, оплаты и отгрузки.
Все 10 сущностей имеют первичный ключ `Id`. Имена в диаграмме соответствуют SQL.

| Сущность | Назначение | Внешние ключи |
|---|---|---|
| Customer | Покупатель | Нет |
| Address | Адрес покупателя | CustomerId |
| Category | Категория товара | Нет |
| Product | Товар, цена и доступный остаток | CategoryId |
| OrderStatus | Справочник состояний заказа | Нет |
| SalesOrder | Заголовок заказа | CustomerId, (CustomerId, AddressId), StatusId |
| OrderItem | Товар в заказе, количество и историческая цена | OrderId, ProductId |
| Payment | Один платёж по заказу | OrderId с UNIQUE |
| DeliveryMethod | Способ и тариф доставки | Нет |
| Shipment | Одна отгрузка заказа | OrderId с UNIQUE, DeliveryMethodId |

## Связи

| Родитель → потомок | Кратность | Смысл |
|---|---|---|
| Customer → Address | 1 : 0..N | У покупателя может быть несколько адресов |
| Customer → SalesOrder | 1 : 0..N | Покупатель оформляет заказы |
| Address → SalesOrder | 1 : 0..N | Один адрес используется в нескольких заказах |
| OrderStatus → SalesOrder | 1 : 0..N | Каждый заказ имеет один статус |
| Category → Product | 1 : 0..N | Каждый товар входит в одну категорию |
| SalesOrder → OrderItem | 1 : 0..N | На уровне SQL заголовок может ещё не иметь позиций |
| Product → OrderItem | 1 : 0..N | Товар встречается в разных заказах |
| SalesOrder → Payment | 1 : 0..1 | Оплата появляется после оформления |
| SalesOrder → Shipment | 1 : 0..1 | Отгрузка появляется после оформления |
| DeliveryMethod → Shipment | 1 : 0..N | Для отгрузки выбран один способ доставки |

BLL требует минимум одну позицию, а DAL сохраняет заголовок и все позиции
одной транзакцией. Составной внешний ключ заказа гарантирует, что адрес
принадлежит тому же покупателю. Внешние ключи включаются на каждом соединении.

## Ограничения и расчёты

`OrderItem` имеет уникальную пару `(OrderId, ProductId)`; BLL объединяет
повторные позиции до сохранения. Количество должно быть больше нуля,
цена и остаток — неотрицательными. Обновление остатка выполняется условно
внутри транзакции, поэтому при изменении цены или нехватке товара весь заказ
откатывается.

Деньги хранятся как `INTEGER` в копейках, в C# используется `long`.
Сумма товаров = Σ(Quantity × UnitPriceCents). Она вычисляется из позиций
и не дублируется в `SalesOrder`. Переполнение проверяется оператором `checked`.
Время сохраняется в UTC в строковом формате ISO 8601.

Тариф доставки хранится в справочнике отдельно. Для учебной модели допустимы
один платёж и одна отгрузка на заказ; частичные оплаты и несколько посылок
потребуют изменения этих ограничений. Пример начальных данных использует
самовывоз с нулевым тарифом.

Справочники, покупатели и товары отделены от документов заказа. Позиции
заказа устраняют связь многие-ко-многим. Копия цены в позиции отражает цену
сделки и сохраняет историю при последующем изменении каталога.
